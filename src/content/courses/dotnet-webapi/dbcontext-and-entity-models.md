## What an entity is

An **entity** is a plain C# class that maps to a database table. There is no base class to inherit and no interface to implement.

```csharp
public class Book
{
    public int Id { get; set; }
    public string Title { get; set; } = "";
    public int Year { get; set; }
    public decimal Price { get; set; }
    public DateTime CreatedAt { get; set; }
}
```

Add it to the context and EF Core will create a `Books` table with five columns:

```csharp
public class AppDbContext : DbContext
{
    public AppDbContext(DbContextOptions<AppDbContext> options) : base(options) { }

    public DbSet<Book> Books => Set<Book>();
}
```

## Conventions do most of the work

EF Core infers a lot from names and types. Learn these and you write far less configuration.

**The table name** comes from the `DbSet` property name. `DbSet<Book> Books` gives a `Books` table.

**The primary key** is a property called `Id`, or `<TypeName>Id`. Both `Id` and `BookId` are found automatically.

**An integer key is generated by the database.** You never set it. EF Core fills it in after `SaveChanges`.

**Column types** follow the C# type:

| C# | SQL Server |
|---|---|
| `int` | `int` |
| `long` | `bigint` |
| `string` | `nvarchar(max)` |
| `decimal` | `decimal(18,2)` |
| `bool` | `bit` |
| `DateTime` | `datetime2` |
| `Guid` | `uniqueidentifier` |

**Nullability** follows nullable reference types. `string Title` becomes `NOT NULL`, and `string? Subtitle` becomes nullable. This is a very good reason to keep `<Nullable>enable</Nullable>` on.

**Foreign keys** are inferred from a property called `<Navigation>Id`:

```csharp
public class Book
{
    public int Id { get; set; }
    public int AuthorId { get; set; }        // the foreign key
    public Author Author { get; set; } = null!;   // the navigation property
}
```

## Two ways to configure

When a convention is wrong, you override it. There are two mechanisms.

**Data annotations** are attributes on the class. Short and local:

```csharp
using System.ComponentModel.DataAnnotations;
using System.ComponentModel.DataAnnotations.Schema;

[Table("tbl_books")]
public class Book
{
    [Key]
    public int BookId { get; set; }

    [Required]
    [MaxLength(200)]
    [Column("book_title")]
    public string Title { get; set; } = "";

    [Column(TypeName = "decimal(10,2)")]
    public decimal Price { get; set; }

    [NotMapped]
    public string DisplayName => $"{Title} ({Year})";

    public int Year { get; set; }
}
```

**The Fluent API** lives in `OnModelCreating`. More verbose, and it can express everything:

```csharp
protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    modelBuilder.Entity<Book>(entity =>
    {
        entity.ToTable("tbl_books");
        entity.HasKey(b => b.BookId);

        entity.Property(b => b.Title)
              .HasColumnName("book_title")
              .HasMaxLength(200)
              .IsRequired();

        entity.Property(b => b.Price)
              .HasPrecision(10, 2);

        entity.Ignore(b => b.DisplayName);

        entity.HasIndex(b => b.Isbn).IsUnique();
    });
}
```

## Which to use

Use **data annotations** for simple things that also matter to your API, such as `[MaxLength]`, because they double as validation hints and Swagger reads them.

Use the **Fluent API** for everything to do with the database: indexes, composite keys, delete behaviour, precision, default values, relationships and query filters. None of these belong on a class that other layers use, and several are impossible as attributes.

If the two conflict, the Fluent API wins.

## Splitting configuration into files

One `OnModelCreating` with twenty entities becomes unreadable. Put each entity's configuration in its own class:

```csharp
public class BookConfiguration : IEntityTypeConfiguration<Book>
{
    public void Configure(EntityTypeBuilder<Book> builder)
    {
        builder.ToTable("Books");
        builder.HasKey(b => b.Id);

        builder.Property(b => b.Title)
               .HasMaxLength(200)
               .IsRequired();

        builder.Property(b => b.Price)
               .HasPrecision(10, 2);

        builder.HasIndex(b => b.Isbn).IsUnique();

        builder.HasOne(b => b.Author)
               .WithMany(a => a.Books)
               .HasForeignKey(b => b.AuthorId)
               .OnDelete(DeleteBehavior.Restrict);
    }
}
```

Then load them all with one line:

```csharp
protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    modelBuilder.ApplyConfigurationsFromAssembly(typeof(AppDbContext).Assembly);
}
```

This is the pattern to use in any project with more than a handful of tables.

## Configuration you will actually reach for

**Indexes**, which make your `WHERE` clauses fast:

```csharp
builder.HasIndex(b => b.Isbn).IsUnique();
builder.HasIndex(b => new { b.AuthorId, b.Year });     // composite
builder.HasIndex(b => b.Title).HasDatabaseName("IX_Books_Title");
```

A unique index is also the only reliable way to prevent duplicates. Validation checks are racy. A constraint is not.

**Default values:**

```csharp
builder.Property(b => b.CreatedAt).HasDefaultValueSql("GETUTCDATE()");
builder.Property(b => b.IsActive).HasDefaultValue(true);
```

**Computed columns:**

```csharp
builder.Property(b => b.TotalWithTax)
       .HasComputedColumnSql("[Price] * 1.2", stored: true);
```

**Concurrency tokens**, so two simultaneous updates cannot silently overwrite each other:

```csharp
builder.Property(b => b.RowVersion).IsRowVersion();
```

**Value conversions**, which store a C# type as something else:

```csharp
// Store an enum as text instead of a number
builder.Property(b => b.Status).HasConversion<string>();

// Store a list of tags as one comma separated column
builder.Property(b => b.Tags)
       .HasConversion(
           v => string.Join(',', v),
           v => v.Split(',', StringSplitOptions.RemoveEmptyEntries).ToList());
```

**Owned types**, for a value object that lives in the parent's table:

```csharp
builder.OwnsOne(o => o.ShippingAddress);
// creates ShippingAddress_Street, ShippingAddress_City and so on
```

## Global query filters

A filter applied to every query for an entity. The classic use is soft delete:

```csharp
builder.HasQueryFilter(b => !b.IsDeleted);
```

Now `db.Books.ToList()` silently excludes deleted rows, everywhere, with no chance of forgetting. When you genuinely need them:

```csharp
var all = await db.Books.IgnoreQueryFilters().ToListAsync();
```

Multi tenant APIs use the same trick for the tenant id.

## Seeding data

For reference data that should always exist:

```csharp
builder.HasData(
    new Author { Id = 1, Name = "Robert C. Martin" },
    new Author { Id = 2, Name = "Martin Fowler" });
```

Seeded rows become part of a migration, so they are inserted when the migration runs. You must supply explicit keys, and changing seed data later generates a new migration that updates it.

## Keep entities free of API concerns

An entity models your data, not your JSON. Two habits keep it clean.

**No validation attributes for API rules.** `[EmailAddress]` on an entity does nothing at the database level and suggests the entity is being used as a DTO.

**No `[JsonIgnore]`.** If you are hiding a field during serialization, the entity is being returned to clients. Return a DTO instead.

`[MaxLength]` is the useful exception, because it genuinely maps to a column size.

## Quick recap

- An entity is a plain class. Conventions find the key, the table name and the column types.
- Nullable reference types decide column nullability, so keep `Nullable` enabled.
- `<Navigation>Id` is recognised as a foreign key automatically.
- Data annotations suit simple, shared rules. The Fluent API handles anything database specific and always wins on conflict.
- Put each entity's configuration in an `IEntityTypeConfiguration<T>` and load them with `ApplyConfigurationsFromAssembly`.
- Unique indexes, not validation, are what actually prevent duplicate rows.
- `HasQueryFilter` applies a condition to every query, which is how soft delete and multi tenancy are done.
- Keep API concerns such as `[JsonIgnore]` and `[EmailAddress]` out of entities.

// Entities plus configuration, organised the way a real project does it.
using Microsoft.EntityFrameworkCore;
using Microsoft.EntityFrameworkCore.Metadata.Builders;
// ---------- Entities: plain classes, no base class, no API attributes
public class Author
{
    public int Id { get; set; }
    public string Name { get; set; } = "";
    public List&lt;Book&gt; Books { get; set; } = new();
}
public enum BookStatus { Draft, InReview, Published }
public class Book
{
    public int Id { get; set; }                       // convention: primary key, identity
    public string Title { get; set; } = "";           // non nullable -&gt; NOT NULL
    public string? Subtitle { get; set; }             // nullable -&gt; NULL
    public string Isbn { get; set; } = "";
    public int Year { get; set; }
    public decimal Price { get; set; }
    public BookStatus Status { get; set; }
    public List&lt;string&gt; Tags { get; set; } = new();   // stored as one column via a converter
    public bool IsDeleted { get; set; }               // soft delete flag
    public DateTime CreatedAt { get; set; }
    public byte[] RowVersion { get; set; } = Array.Empty&lt;byte&gt;();
    public int AuthorId { get; set; }                 // convention: foreign key
    public Author Author { get; set; } = null!;       // navigation property
    // Not a column: computed in C# only
    public string DisplayName =&gt; $"{Title} ({Year})";
}
// ---------- One configuration class per entity keeps OnModelCreating empty
public class BookConfiguration : IEntityTypeConfiguration&lt;Book&gt;
{
    public void Configure(EntityTypeBuilder&lt;Book&gt; builder)
    {
        builder.ToTable("Books");
        builder.HasKey(b =&gt; b.Id);
        builder.Property(b =&gt; b.Title).HasMaxLength(200).IsRequired();
        builder.Property(b =&gt; b.Subtitle).HasMaxLength(200);
        builder.Property(b =&gt; b.Isbn).HasMaxLength(13).IsFixedLength();
        builder.Property(b =&gt; b.Price).HasPrecision(10, 2);
        // A unique index is the only reliable duplicate guard. Validation is racy.
        builder.HasIndex(b =&gt; b.Isbn).IsUnique();
        builder.HasIndex(b =&gt; new { b.AuthorId, b.Year });
        // Store the enum as readable text rather than an int
        builder.Property(b =&gt; b.Status).HasConversion&lt;string&gt;().HasMaxLength(20);
        // Store List&lt;string&gt; as one comma separated column
        builder.Property(b =&gt; b.Tags)
               .HasConversion(
                   v =&gt; string.Join(',', v),
                   v =&gt; v.Split(',', StringSplitOptions.RemoveEmptyEntries).ToList())
               .HasMaxLength(500);
        builder.Property(b =&gt; b.CreatedAt).HasDefaultValueSql("GETUTCDATE()");
        // Two simultaneous updates now conflict instead of silently overwriting
        builder.Property(b =&gt; b.RowVersion).IsRowVersion();
        builder.Ignore(b =&gt; b.DisplayName);           // computed in C#, not a column
        builder.HasOne(b =&gt; b.Author)
               .WithMany(a =&gt; a.Books)
               .HasForeignKey(b =&gt; b.AuthorId)
               .OnDelete(DeleteBehavior.Restrict);    // do not delete books with the author
        // Every query for Book gets this automatically. Bypass with IgnoreQueryFilters().
        builder.HasQueryFilter(b =&gt; !b.IsDeleted);
    }
}
public class AuthorConfiguration : IEntityTypeConfiguration&lt;Author&gt;
{
    public void Configure(EntityTypeBuilder&lt;Author&gt; builder)
    {
        builder.Property(a =&gt; a.Name).HasMaxLength(120).IsRequired();
        builder.HasIndex(a =&gt; a.Name);
        // Reference data that ships with the migration
        builder.HasData(
            new Author { Id = 1, Name = "Robert C. Martin" },
            new Author { Id = 2, Name = "Martin Fowler" });
    }
}
// ---------- The context stays tiny
public class AppDbContext : DbContext
{
    public AppDbContext(DbContextOptions&lt;AppDbContext&gt; options) : base(options) { }
    public DbSet&lt;Book&gt;   Books   =&gt; Set&lt;Book&gt;();
    public DbSet&lt;Author&gt; Authors =&gt; Set&lt;Author&gt;();
    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        // Finds and applies every IEntityTypeConfiguration in this assembly
        modelBuilder.ApplyConfigurationsFromAssembly(typeof(AppDbContext).Assembly);
    }
}
